# 커리어 내비 기능 명세 요약

> 강사 설명용 · 기능 기준 `feat/employer-mock` / `c0b304e` · 2026-09-08

## 1. 서비스 한 문장

커리어 내비는 **직무명이 아니라 보유 역량과 요구 역량을 연결해**, 개인에게는 다음 커리어 경로를, 기업에는 직무명 검색으로 놓칠 수 있는 후보를 보여주는 양방향 채용 목업이다.

```text
개인  이력서 역량  → 갈 수 있는 직무 3개
기업  공고의 역량  → 맞는 지원자·추천 인재
                   ↑
        공통 직무·역량 ID와 가중 커버율
```

## 2. 이번 목업의 핵심

| 구분 | 구현 내용 | 현재 성격 |
|---|---|---|
| 개인 분석 | 이력서 텍스트에서 역량을 추출하고 커리어 경로 3개 제시 | 동작 기능 |
| 결과 설명 | 보유·대체·부족 역량과 첫 학습 단계 표시 | 동작 기능 |
| 회사 탐색 | 회사 18개와 공고 48개 조회 | 가상 데이터 목업 |
| 기존 지원자 관리 | 공고별 지원자 검색·필터·상세·전형 상태 변경 | 가상 데이터·세션 상태 |
| 새 공고 작성 | 직접 작성 또는 AI 문구 초안 | 저장 없는 목업 |
| 인재풀 추천 | 작성 공고로 후보 72명을 다시 평가 | 가상 데이터 목업 |

실제 회원, 기업, 지원자와 채용 행위는 사용하지 않는다. 화면과 데이터 계약, 추천 근거가 자연스럽게 이어지는지를 보여주는 데 목적이 있다.

## 3. 일반 사용자 흐름

### 3.1 입력

- 준비된 샘플 프로필을 선택하면 AI 호출 없이 즉시 결과를 확인한다.
- 자유 입력은 120~12,000자의 이력서 텍스트를 받는다.
- 실제 AI 제공자를 사용하면 Gemini 또는 Anthropic에 분석을 요청한다.
- 서버나 DB에는 이력서와 결과를 저장하지 않는다.

### 3.2 분석

1. 코드가 등록된 298개 역량의 원문 언급을 먼저 찾는다.
2. LLM이 현재 직무·경력·산업·역량 후보를 추출한다.
3. 원문에서 근거를 다시 확인할 수 없는 역량을 제거한다.
4. 24개 직무의 요구 역량과 비교해 코드가 점수와 순위를 계산한다.

LLM은 문장을 해석하지만 **점수를 직접 만들지 않는다**. 같은 추출 결과에는 같은 점수가 나오도록 계산을 코드에 고정했다.

### 3.3 결과

- 추천 커리어 경로 3개
- 필수·우대 역량 충족 근거
- 같은 역량 묶음으로 대체 충족한 항목
- 부족 역량과 첫 학습 단계
- 예상 준비 기간과 관련 가상 공고
- 다른 직군이지만 근거가 충분한 경우 `이 길도 있어요` 경로

현재 개인 화면에서는 적합도 숫자를 숨기고 충족 근거와 추천 순서를 우선해 보여준다. 점수 자체는 내부 계약에 남아 있어 필요하면 다시 표시할 수 있다.

## 4. 회사·공고·지원 흐름

### 4.1 회사와 공고 조회

- 회사명, 산업, 소개와 태그 검색
- 회사 소개, 제품, 위치, 문화, 복지와 채용 절차
- 공고의 주요 업무, 필수·우대 역량, 경력, 근무 방식, 연봉 표시

회사명, 브랜드, 채용 조건은 모두 가상이다. 실제 서비스로 전환할 때 화면을 다시 만들지 않도록 실제 데이터가 들어갈 필드 구조를 먼저 맞췄다.

### 4.2 지원 체험

공고 상세에서 지원 화면까지 이동할 수 있지만 버튼은 브라우저 상태만 완료로 바꾼다. 입력 폼, 파일 전송, 실제 회사 전달과 저장은 없다.

## 5. 기업 사용자 흐름

### 5.1 기존 지원자 관리

```text
가상 회사 선택 → 기존 공고 선택 → 지원자 검색·필터 → 근거 확인 → 전형 상태 변경
```

- 지원자 별칭, 현재 직무와 역량 검색
- 전형 단계, 신입·경력, 최소 적합도 필터
- 현재 직무명이 다른 전환 후보 포함 여부
- 일치 역량의 문장 근거, 부족 역량, 경력 범위 충족 여부
- 전형 상태 변경은 새로고침하면 초기화

### 5.2 새 공고와 AI 초안

```text
회사 선택 → 직무·근무 조건·역량 선택 → 직접 작성 또는 AI 초안 → 담당자 검토
          → 같은 조건으로 가상 인재풀 72명 재평가
```

- 직무를 고르면 데이터에서 필수·우대 역량을 제안한다.
- AI는 공고 제목, 소개와 주요 업무 문구만 작성한다.
- 직무와 역량 ID, 경력 구간, 적합도는 코드가 결정한다.
- 민감 조건과 확인 불가능한 보장 표현은 검토 경고로 표시한다.
- 초안, 추천 결과와 상태는 실제로 게시하거나 저장하지 않는다.
- 추천 후보는 지원자가 아니므로 `미지원·연락 기능 없음`을 명시한다.

## 6. 적합도 해석

### 개인 커리어 경로

```text
필수 커버율 × 3 + 우대 커버율 × 1 + 전이 가능한 강점 × 2
→ 경력 부족 보정
→ 현재 직무가 정확히 같으면 최대 8점 추가
```

### 기업 후보

```text
필수 커버율 × 3 + 우대 커버율 × 1
```

두 점수는 목적과 항목이 달라 서로 직접 비교하지 않는다. 기업 점수의 경력 조건은 현재 별도 `충족 여부`로 보여주며 숫자에는 넣지 않았다. 희망 근무 방식도 현재 숫자에 반영하지 않는다.

커버율은 단순 개수가 아니다. 각 역량이 해당 직무의 실제 분석 공고에 얼마나 자주 등장했는지를 가중치로 사용한다. 같은 그룹의 대체 역량도 별도로 기록해 설명할 수 있다.

## 7. 데이터 구성

| 데이터 | 수량 | 역할 |
|---|---:|---|
| 직무 | 24 | 추천 목적지와 채용 직무 |
| 역량 | 298 | 이력서와 공고의 공통 어휘 |
| 직무-역량 매핑 | 1,509 | 가중 커버율 계산 |
| 분석 채용공고 | 1,435 | 직무별 역량 빈도 근거 |
| 가상 회사 | 18 | 회사 탐색·기업 계정 목업 |
| 가상 공고 | 48 | 공고 조회·지원자 연결 |
| 가상 후보 | 72 | 기존 지원자·인재풀 추천 |
| 가상 지원 이력 | 288 | 공고별 전형 상태 |

가상 데이터는 실제 회사·인물·로고·이력서를 복제하지 않았으며 추천 품질 평가용 정답으로도 사용하지 않는다.

- 텍스트를 제목·본문·메타·비활성의 네 단계로 구분

## 11. 시연할 때 권장 순서

1. 랜딩에서 개인과 기업이 같은 역량 체계를 반대 방향으로 사용함을 설명한다.
2. 개인 샘플을 선택해 추천 3개와 역량 근거를 펼친다.
3. 회사와 공고 상세에서 실제 서비스 교체를 고려한 필드 구조를 보여준다.
4. 기업 화면에서 직무명이 다른 후보가 역량으로 잡히는 장면을 보여준다.
5. 새 공고를 AI로 만들고 `AI는 문구만, 점수는 코드가 계산`함을 설명한다.
6. 추천 인재가 실제 지원자가 아니며 모든 기업 데이터가 가상임을 다시 밝힌다.

## 12. 현재 한계와 다음 작업

### 목업 신뢰성을 위해 먼저 할 것

1. 기업의 역량 적합도와 경력·근무 조건을 더 명확히 분리 표시
2. 개인·회사·지원·기업 공고 흐름의 브라우저 E2E 테스트
3. 구형 기업 공유 이미지 데이터 계약 정리
4. AI 입력 문맥과 공고 전체 필드 검증 강화

### 실제 서비스 전환 시 필요한 것

- 회원·기업 인증과 권한
- DB와 공고 게시 API
- 이력서 파일 파싱과 다건 처리
- 실제 지원·연락·알림
- 개인정보 동의·보관·파기 정책
- 여러 서버가 공유하는 호출 제한

현재 결과물은 위 운영 기능이 완성됐다고 주장하지 않는다. **가상 데이터로 사용자 흐름과 설명 가능한 역량 매칭 구조를 검증한 목업**이다.
