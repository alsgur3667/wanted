# 커리어 내비 기능 명세

> 기능 기준 브랜치·커밋: `feat/employer-mock` · `c0b304e`<br>
> 확인일: 2026-09-08<br>
> 이 문서는 기획 의도가 아니라 **현재 코드에서 실제로 동작하는 범위**를 명세한다.

강사 설명과 빠른 검토에는 [기능 명세 요약본](./FUNCTIONAL_SPEC_BRIEF.md)을 먼저 사용한다.

## 1. 문서 목적

커리어 내비의 현재 사용자 기능, 기업 기능, API, 점수 계산, 가상 데이터, 저장 범위와 제약을 한 문서에서 확인하기 위한 명세다.

현재 서비스는 다음 두 흐름을 제공한다.

```text
개인: 이력서 텍스트 → 역량 추출 → 커리어 경로 3개
기업: 채용공고 선택·작성 → 기존 지원자 검토 / 가상 인재풀 추천
```

두 흐름은 24개 직무와 298개 역량의 공통 ID 체계 및 가중 커버율 규칙을 사용한다. 다만 개인용 점수와 기업용 점수는 목적이 달라 세부 산식이 동일하지 않다.

### 상태 표기

| 상태 | 의미 |
|---|---|
| 구현 | 현재 화면 또는 API에서 사용할 수 있음 |
| 목업 | 동작하지만 가상 데이터 또는 브라우저 임시 상태만 사용함 |
| 부분 구현 | 기반 코드는 있으나 화면·저장·운영 기능 중 일부가 없음 |
| 미구현 | 현재 코드에서 제공하지 않음 |

## 2. 제품 범위

### 2.1 사용자 역할

| 역할 | 현재 제공 범위 |
|---|---|
| 일반 사용자 | 이력서 텍스트 분석, 추천 경로 확인, 회사·공고 조회, 지원 흐름 체험 |
| 기업 사용자 | 가상 회사·공고 선택, 기존 지원자 검토, 공고 직접 작성 또는 AI 초안 생성, 가상 인재풀 추천 |

현재 인증과 권한 구분은 없다. 누구나 일반·기업 화면에 접근하고 어느 가상 회사든 선택할 수 있다.

### 2.2 현재 범위 밖

- 회원가입·로그인·기업 계정 인증
- 이력서 파일 업로드와 다건 분석
- 분석 결과·공고 초안·전형 상태의 DB 저장
- 실제 채용공고 게시·수정·마감
- 실제 지원서 제출, 파일 첨부, 지원 철회
- 지원자 연락, 메시지, 인터뷰 일정 관리
- 결제, 알림, 관리자 화면
- 실제 회사·지원자 데이터 연동

## 3. 화면 및 엔드포인트 목록

| 경로 | 유형 | 상태 | 용도 |
|---|---|---|---|
| `/` | 화면 | 구현 | 개인·기업 흐름 진입 및 회사 탐색 링크 |
| `/personal` | 화면 | 구현 | 이력서 입력, 샘플 선택, 분석 결과 확인 |
| `/companies` | 화면 | 목업 | 가상 회사 목록 검색 |
| `/companies/[companyId]` | 화면 | 목업 | 가상 회사 상세와 채용공고 확인 |
| `/jobs/[postingId]` | 화면 | 목업 | 가상 채용공고 상세 확인 |
| `/jobs/[postingId]/apply` | 화면 | 목업 | 저장 없는 지원 완료 흐름 체험 |
| `/employer` | 화면 | 목업 | 기존 지원자 관리와 새 공고 작성 |
| `POST /api/analyze` | API | 구현 | 이력서 역량 추출 및 개인 추천 계산 |
| `POST /api/employer/posting-draft` | API | 구현 | AI 채용공고 문구 초안 생성 |
| `GET /api/og/personal` | 이미지 API | 구현 | 개인 결과 공유용 1200×630 이미지 생성 |
| `GET /api/og/employer` | 이미지 API | 부분 구현 | 이전 기업 발표 데이터 기반 이미지 생성 |

회사 18개와 공고 48개는 정적 경로를 미리 생성한다. 존재하지 않는 회사·공고 ID는 404로 처리한다.

## 4. 공통 기능

### COM-01 랜딩과 역할 분기

- 상태: 구현
- 사용자는 첫 화면에서 `개인` 또는 `기업` 흐름을 선택할 수 있다.
- 별도 링크로 가상 회사 목록에 진입할 수 있다.
- 로그인이나 역할 확인 없이 각 화면으로 이동한다.

### COM-02 밝은·어두운 테마

- 상태: 구현
- 사용자는 테마 버튼으로 밝은 모드와 어두운 모드를 전환할 수 있다.
- 선택값은 브라우저 `localStorage`의 `theme` 키에 저장된다.
- 저장값이 없으면 운영체제 테마를 따른다.
- 초기 렌더링 전에 저장값을 적용해 화면 깜박임을 줄인다.

### COM-03 공통 시각 체계와 반응형 화면

- 상태: 구현
- 제목·본문·메타데이터·비활성 정보는 `ink`, `body`, `mute`, `faint` 네 단계로 구분한다.
- 청록색은 보유 역량, 선택 상태와 정상 완료처럼 긍정적인 신호에 사용한다.
- 앰버색은 숨은 경로, 직무 전환 후보와 검토 경고에 사용한다.
- 카드 구조는 그림자보다 `hairline` 테두리와 배경 단계로 구분한다.
- 입력과 주요 버튼은 작은 `rounded-md`, 콘텐츠 카드는 `rounded-xl`을 기본으로 사용한다.
- 등장·펼침 애니메이션은 `prefers-reduced-motion` 설정에서 비활성화한다.
- 기업 지원자 관리와 공고 작성·추천 흐름은 1440px 데스크톱과 390px 모바일에서 실제 렌더링을 확인했다.

## 5. 일반 사용자 기능

### PER-01 샘플 프로필 분석

- 상태: 구현
- 사용자는 준비된 샘플 프로필을 선택해 즉시 결과를 볼 수 있다.
- 샘플 결과는 미리 계산되어 있으며 `/api/analyze`나 외부 AI를 호출하지 않는다.
- 심사·시연 중 외부 AI 장애나 비용과 무관하게 핵심 결과 화면을 확인하기 위한 기능이다.

### PER-02 자유 형식 이력서 분석

- 상태: 구현
- 입력은 일반 텍스트 한 필드다.
- 앞뒤 공백을 제거한 길이가 120자 이상, 12,000자 이하여야 한다.
- 분석 중 로딩 상태와 실패 메시지를 표시한다.
- 성공하면 입력 화면을 결과 화면으로 전환한다.
- 서버나 DB에는 이력서와 결과를 저장하지 않는다.
- `gemini` 또는 `anthropic`을 사용하면 이력서 원문이 분석을 위해 해당 제공자에게 전송된다.

`targetJob`은 API 계약과 추출 프롬프트에는 있으나 현재 개인 화면에서 입력할 수 없다.

### PER-03 역량 추출

- 상태: 구현
- 제공자: Gemini, Anthropic, 결정론적 mock.
- 명시한 제공자의 키가 없거나 호출이 실패하면 오류를 반환하며 mock으로 조용히 대체하지 않는다.
- 제공자가 지정되지 않았으면 Gemini 키, Anthropic 키 순으로 사용한다.
- 프로덕션에서 제공자와 키가 모두 없으면 실패한다. 비프로덕션에서는 mock을 사용할 수 있다.
- LLM은 현재 직무·경력·산업·역량 후보를 추출한다.
- 점수와 추천 순서는 LLM이 아니라 코드가 계산한다.
- 추출한 역량은 온톨로지에 등록된 ID로 정규화하고, 이력서 원문에서 근거를 다시 찾을 수 없는 항목은 제거한다.
- 경력 개월 수는 원문에서 규칙으로 계산할 수 있으면 코드 결과로 보정한다.

### PER-04 현재 위치와 추천 경로 3개

- 상태: 구현
- 결과 상단에 현재 직무, 경력, 산업, 한 줄 요약을 표시한다.
- 추천 경로는 항상 3개를 제공한다.
- 기본 화면에서는 세 경로를 접은 상태로 보여준다.
- 현재 개인 UI는 적합도 숫자를 의도적으로 숨긴다. 내부 `fitScore`는 계산·전달되며 검토용 상수로 다시 표시할 수 있다.
- 대신 필수 역량 충족 개수와 순서 근거를 보여준다.
- 다른 직군으로의 이동 근거가 충분하면 `이 길도 있어요` 성격의 숨은 경로를 포함할 수 있다. 근거가 부족하면 억지로 만들지 않는다.

### PER-05 경로 상세 근거

- 상태: 구현
- 경로를 펼치면 다음 정보를 확인할 수 있다.
  - 필수·우대 역량과 충족 여부
  - 이력서 원문에서 확인한 보유 역량 근거
  - 동일 역량 묶음의 대체재로 충족한 항목
  - 부족 역량과 첫 학습 단계
  - 예상 준비 기간
  - 표본이 작은 직무에 대한 주의
  - 해당 직무의 가상 채용공고 최대 2건
- 연봉 구간과 직업 전망은 원천 데이터가 있는 직무에만 표시할 수 있다.

### PER-06 추천 순위 설명

- 상태: 구현
- 세 경로를 필수·우대 충족 수와 함께 표로 비교한다.
- 높은 점수가 낮은 점수 아래로 내려가지 않도록 사용자 표시 점수를 1차 정렬 기준으로 사용한다.
- 표본 신뢰도와 직무 보정값은 동점 처리와 숨은 경로 판단에만 사용하며 사용자 점수로 표시하지 않는다.

### PER-07 다른 직무 탐색

- 상태: 구현
- 추천된 3개 외의 직무를 사용자가 직접 선택해 요구 역량과 본인 역량을 비교할 수 있다.
- 이 결과는 추천 목록에 포함된 것으로 표현하지 않는다.

### PER-08 보유 역량 분류와 지도

- 상태: 구현
- 추출된 역량을 전이 무기, 도메인 락인, 공통 역량으로 나눠 표시한다.
- 각 그룹은 처음에 최대 6개를 표시하고 나머지는 펼칠 수 있다.
- 노이즈 사분면은 목록에서 숨긴다.
- 사용자는 확산성·희소성 기반 2×2 역량 지도를 선택적으로 펼칠 수 있다.

### PER-09 결과 공유 이미지

- 상태: 구현
- 사용자는 개인 결과의 요약 문구를 복사하거나 PNG 이미지를 받을 수 있다.
- 공유 정보는 현재 직무, 경력, 목적지, 필수 역량 충족 수, 브리지 역량 최대 3개로 제한한다.
- 이력서 원문과 상세 근거는 이미지 URL의 쿼리에 넣지 않는다.
- 공유 문구에 포함되는 서비스 URL은 현재 하드코딩된 대회 데모 URL이다.

## 6. 회사·채용공고·지원 기능

### JOB-01 회사 목록 검색

- 상태: 목업
- 18개 가상 회사를 카드로 보여준다.
- 회사명, 산업, 한 줄 소개, 태그를 대상으로 한 통합 검색을 제공한다.
- 카드에는 산업, 규모, 성장 단계, 근무 방식, 진행 중인 공고 수를 표시한다.
- 현재 데이터 규모에서는 페이지네이션을 제공하지 않는다.

### JOB-02 회사 상세

- 상태: 목업
- 회사 소개, 제품, 위치, 근무 방식, 문화, 복지, 채용 절차를 표시한다.
- 해당 회사의 진행 중인 가상 공고 목록을 연결한다.
- 가상 회사는 실제 웹사이트와 실제 로고를 사용하지 않고 이니셜 기반 브랜드 표식을 사용한다.

### JOB-03 채용공고 상세

- 상태: 목업
- 회사, 직무, 경력 구간, 고용 형태, 근무 방식, 위치, 게시일, 마감 방식, 연봉 표시를 제공한다.
- 주요 업무, 필수·우대 역량, 복지, 채용 절차와 제출 서류를 표시한다.
- 역량은 298개 온톨로지의 ID를 참조한다.
- 모든 공고는 공개 상태인 가상 공고다.

### JOB-04 지원 체험

- 상태: 목업
- 사용자는 공고 상세에서 지원 화면으로 이동할 수 있다.
- 지원 화면은 제출 서류와 절차를 안내한다.
- 버튼을 누르면 같은 페이지의 브라우저 상태만 완료로 변경한다.
- 입력 폼, 파일 업로드, 네트워크 요청, 저장, 실제 회사 전송은 없다.

## 7. 기업 사용자 기능

### EMP-01 기업 작업공간 전환

- 상태: 목업
- `/employer`에서 `지원자 관리`와 `새 공고 만들기` 탭을 전환한다.
- 기업 사용자는 18개 가상 회사 중 하나를 선택할 수 있다.
- 회사 선택은 인증된 소유권을 뜻하지 않는다.

### EMP-02 기존 지원자 관리

- 상태: 목업
- 선택한 회사와 공고에 연결된 가상 지원자를 적합도 높은 순으로 보여준다.
- 다음 검색·필터를 제공한다.
  - 지원자 별칭, 현재 직무, 역량 검색
  - 전형 단계: 신규, 검토, 인터뷰, 오퍼, 보류, 불합격
  - 경력: 전체, 신입(12개월 미만), 경력
  - 최소 적합도: 0, 40, 60, 80
  - 현재 직무명이 다른 전환 후보 포함 여부
- 전체 지원 수, 보류·불합격을 제외한 활성 수, 다른 직무 후보 수, 평균 적합도를 표시한다.

### EMP-03 지원자 상세와 전형 상태 변경

- 상태: 목업
- 선택한 지원자의 현재 직무, 경력, 위치, 희망 근무 방식, 요약을 확인한다.
- 적합도, 필수·우대 커버율, 일치 역량 근거, 대체 역량, 부족 역량, 온보딩 추정, 경력 범위 충족 여부를 표시한다.
- 전형 단계를 화면에서 변경할 수 있다.
- 변경값은 React 메모리에만 남고 새로고침하면 원본 가상 데이터로 돌아간다.

### EMP-04 채용공고 직접 작성

- 상태: 목업
- 작성 회사, 직무, 레벨, 고용 형태, 근무 방식, 위치를 선택한다.
- 직무를 선택하면 직무 데이터의 필수·우대 역량을 초기값으로 제안한다.
- 사용자는 298개 등록 역량 안에서 필수·우대 목록을 추가·삭제할 수 있다.
- 같은 역량을 필수와 우대에 동시에 넣을 수 없다.
- 제목, 소개, 주요 업무를 직접 입력해 검토용 초안을 만든다.
- 작성한 초안은 저장하거나 실제 공고로 게시하지 않는다.

### EMP-05 AI 채용공고 초안

- 상태: 구현
- 사용자는 담당 업무나 해결할 문제를 10~1,200자로 입력한다.
- AI는 제목, 소개, 주요 업무 문구만 생성한다.
- 회사·직무·역량 ID, 경력 범위와 점수는 코드가 결정·검증한다.
- AI가 새 역량을 임의로 만들거나 등록되지 않은 역량을 반환하는 구조가 아니다.
- Gemini, Anthropic, mock 제공자를 지원하며 외부 제공자 실패 시 자동으로 mock 결과를 내지 않는다.
- 결과에는 실제 사용한 제공자를 표시한다.

### EMP-06 초안 검토와 경고

- 상태: 부분 구현
- 제목은 2~80자, 소개는 20~500자, 주요 업무는 2~8개이며 각 항목은 5~160자여야 한다.
- 필수 역량은 1~10개, 우대 역량은 최대 10개다.
- 알 수 없는 회사·직무·역량 ID, 지원하지 않는 열거값, 필수·우대 중복은 요청 단계에서 거절한다.
- 성별, 나이, 혼인·임신, 외모, 출신 학교·지역 관련 표현과 `무조건`, `100%`, `평생 보장` 같은 확인 불가능한 표현은 **차단이 아니라 검토 경고**로 표시한다.
- AI 초안 생성 직후 경고 검사는 생성된 제목·소개·업무를 대상으로 한다. 사용자가 입력한 AI 문맥 자체는 생성 직후 별도 경고 대상으로 완전히 다뤄지지 않는다.
- 초안을 수정하면 기존 미리보기와 추천 결과를 숨기고 `수정 내용 반영` 후 다시 계산한다.
- 복지, 채용 절차, 제출 서류, 연봉은 선택 회사의 기본값을 사용하며 현재 작성 화면에서 직접 편집하지 않는다.

### EMP-07 새 공고 기반 인재풀 추천

- 상태: 목업
- 검토된 초안의 필수·우대 역량으로 가상 지원자 72명 전원을 다시 평가한다.
- 기본 최소 적합도는 40점이며, 필터를 통과한 결과 중 최대 18명을 표시한다.
- 검색, 최소 적합도, 다른 직무 전환 후보 포함 여부 필터를 제공한다.
- 추천 대상은 기존 지원자가 아니며 `미지원`, `연락 기능 없음`으로 표시한다.
- 후보 상세에서 적합도, 필수·우대 커버율, 역량 근거와 부족 역량을 확인한다.
- 후보에게 연락하거나 기존 지원자로 전환하는 기능은 없다.

## 8. 점수 및 추천 규칙

### 8.1 개인 커리어 경로 점수

```text
baseFit  = 100 × (필수 커버율 × 3 + 우대 커버율 × 1 + 강점 반영 × 2) / 6
fitScore = round(baseFit × 경력 적합도 + 현재 직무 일치 보너스)
```

- 커버율은 단순 보유 개수가 아니라 해당 직무 공고에서의 등장 빈도 가중치를 사용한다.
- 같은 역량 그룹의 대체재가 있으면 요구 역량을 대체 충족할 수 있다.
- 경력이 부족한 경우에만 신입 비율을 바탕으로 0.65~1.0 배율을 적용하며 경력이 많다는 이유로 점수를 올리지는 않는다.
- 현재 직무 ID가 정확히 같으면 최대 8점을 더한다.
- 내부 `evidenceScore`는 표본 신뢰도와 직무 보정을 반영하지만, 표시 점수나 1차 정렬을 대신하지 않는다.
- 숨은 경로는 다른 직군이면서 일정 수준 이상의 근거와 교차 직군 역량을 충족할 때만 후보가 된다.
- 예상 준비 기간은 부족 역량의 학습 난이도 합에 3개월을 곱한 규칙 기반 추정치다. 실제 학습 기간 예측값이 아니다.

### 8.2 기업 지원자·인재풀 점수

```text
fitScore = round(100 × (필수 커버율 × 3 + 우대 커버율 × 1) / 적용 가중치 합)
```

- 필수·우대 커버율은 개인 기능과 같은 수요 가중치와 대체 역량 그룹을 사용한다.
- 후보의 경력 범위 충족 여부는 `careerFit`으로 별도 계산·표시한다.
- 현재 기업 적합도 숫자에는 경력 범위와 희망 근무 방식이 반영되지 않는다.
- 정렬은 적합도 내림차순, 동점이면 경력 범위 충족 후보 우선이다.
- 온보딩 기간은 부족 역량 난이도 기반 목업 추정치다.

개인 점수와 기업 점수는 서로 직접 비교할 수 없다. 개인 점수에는 강점·경력·현재 직무 항이 있고 기업 점수에는 필수·우대 커버율만 들어간다.

## 9. API 계약

### API-01 `POST /api/analyze`

요청:

```json
{
  "resumeText": "120~12000자의 이력서 텍스트",
  "targetJob": "선택 문자열, 최대 200자만 사용"
}
```

성공: HTTP 200, `{ "ok": true, "data": AnalysisResult }`<br>
실패: `{ "ok": false, "code": "TOO_SHORT | RATE_LIMIT | LLM_FAILED | UNKNOWN", "message": "..." }`

- 호출 상한 기본값은 프로세스별 UTC 하루 150회다.
- 상한은 `DAILY_CALL_LIMIT`로 바꿀 수 있다.
- 외부 제공자 호출 실패도 호출 횟수에 포함된다.
- 모든 응답에 `Cache-Control: no-store`를 설정한다.

### API-02 `POST /api/employer/posting-draft`

요청 필드:

- `companyId`, `jobId`
- `level`, `employmentType`, `workMode`, `location`
- `context`
- `mustSkillIds`, `niceSkillIds`

성공: HTTP 200, `{ "ok": true, "data": PostingDraft, "provider": "gemini | anthropic | mock", "warnings": [] }`<br>
실패: `{ "ok": false, "code": "INVALID_INPUT | RATE_LIMIT | LLM_FAILED", "message": "..." }`

- 호출 상한 기본값은 프로세스별 UTC 하루 80회다.
- 상한은 `POSTING_DRAFT_DAILY_LIMIT`로 바꿀 수 있다.
- 실패 응답은 발견된 검증 오류 중 첫 항목만 반환한다.
- 모든 응답에 `Cache-Control: no-store`를 설정한다.

### API-03 `GET /api/og/personal`

- 쿼리 문자열로 현재 직무, 경력, 목적지, 필수 충족 수와 브리지 역량을 받는다.
- 1200×630 PNG를 동적으로 생성한다.
- 개인 적합도 숫자와 이력서 원문은 카드에 표시하지 않는다.
- 쿼리 값은 공유 정보이므로 민감정보를 넣지 않는 것을 전제로 한다.

### API-04 `GET /api/og/employer`

- 상태: 부분 구현, 현재 기업 화면에서 직접 연결되지 않은 이전 발표용 엔드포인트.
- `job` 쿼리로 이전 `JobRequirement` 샘플을 선택한다.
- 현재 72명 인재풀과 288건 지원 이력이 아니라 `data/candidates.ts`, `data/job-requirements.ts`, `lib/matching.ts`의 구형 데이터·계약을 사용한다.
- 기업 화면과 같은 결과라고 간주하면 안 된다.

## 13. 검증 범위

`npm run verify`는 다음을 순서대로 실행한다.

1. ESLint
2. Vitest 단위·API 테스트
3. Python 수집 도구 테스트
4. 원본·중간 직무/역량 데이터 계약 검사
5. 가상 회사·공고·지원자 데이터 검사
6. Next.js production build

기능 기준 커밋에서 확인된 자동 테스트는 Vitest 12개 파일 53건, Python 4건이다.

주요 자동 검증 대상:

- 이력서 API의 입력 오류와 mock 관통 흐름
- 공고 AI API의 입력 오류와 mock 관통 흐름
- 직무·역량 정규화, 대체 역량, 개인 점수·정렬·숨은 경로
- 회사·공고 참조 무결성
- 지원자·지원 이력 연결 및 기업 매칭
- 공고 초안 계약과 경고 문구
- 가상 데이터 생성·큐레이션 규칙

현재 Playwright·Cypress 같은 실제 브라우저 E2E 테스트와 외부 Gemini·Anthropic 실호출 통합 테스트는 없다. 따라서 자동 검증 통과가 배포 환경의 외부 API, 폰트 네트워크, 모든 반응형 UI 동작까지 보장하지는 않는다.

수동 UI 검증에서는 다음 흐름을 확인했다.

- 1440px 데스크톱 기업 지원자 관리 화면
- 390px 모바일 화면의 가로 넘침 없음
- 기업 `새 공고 만들기` 탭 전환
- mock AI 초안 생성 성공과 생성 제공자 표시
- 생성한 초안을 기준으로 가상 추천 인재 노출

| 중간 | `PostingDraft` 전체 필드의 런타임 재검증이 제한적 | 내부 호출 경로가 늘면 타입 밖 입력을 놓칠 수 있음 | 게시 전 최종 스키마 검증 추가 |
| 낮음 | `targetJob`이 API에만 존재 | 사용자가 관심 직무를 화면에서 전달할 수 없음 | UI에 노출하거나 계약에서 제거 |
| 낮음 | 공유 URL이 하드코딩됨 | 배포 주소가 바뀌면 복사 문구가 오래된 주소를 가리킴 | 환경 변수나 현재 origin 사용 |
| 낮음 | 43개 역량이 직무 매핑에서 미사용 경고 | 데이터 후보 일부가 추천에 기여하지 않음 | 실제 공고 근거 확보 후 매핑 또는 제거 판단 |
| 낮음 | OG 한글 폰트가 외부 네트워크에 의존 | 네트워크 실패 시 fallback 글꼴로 렌더링될 수 있음 | 로컬 폰트 번들 또는 배포 환경 캐시 검토 |

## 15. 변경 관리

다음 변경이 생기면 이 문서를 함께 갱신한다.

- 화면 또는 API 경로 추가·삭제
- `types.ts`의 공개 계약 변경
- 개인·기업 점수 산식 또는 정렬 기준 변경
- 가상 데이터 수량·필드·생성 원칙 변경
- 저장·인증·외부 전송 범위 변경
- 구현 상태가 목업에서 실제 연동으로 변경

미래 기능과 우선순위는 [ROADMAP](./ROADMAP.md), 데이터 필드의 상세 규칙은 [DATA_SPEC](./DATA_SPEC.md)와 [COMPANY_DATA](./COMPANY_DATA.md)를 단일 출처로 사용한다.
