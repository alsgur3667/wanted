# Career Navi — AI 활용 방식 및 결과

작성일: 2026-09-14 · 확인 기준: `feat/result-ui-v2`, `6b38a53`

이 문서는 서비스 내부의 AI 기능과 개발 과정에서 사용한 AI를 나누어 설명합니다. 구현 근거와 검증 기록은 [AI 활용 근거 목록](./AI_USAGE_EVIDENCE.md)에 정리했습니다. 코드가 존재하는 것과 실제 외부 모델의 품질이 검증된 것은 구분합니다.

## 1. 프로젝트와 AI 활용 목적

Career Navi는 개인의 이력서에서 확인한 역량을 직무 요구와 연결하고, 기업에는 공고 작성과 역량 기반 후보 탐색을 제공하는 양면 플랫폼입니다. 개인에게는 가능한 직무 경로와 부족 역량을, 기업에는 공고의 요구 역량에 대응하는 후보 근거를 보여주는 것이 목적입니다.

AI 활용은 두 영역으로 나누었습니다.

- **서비스 AI:** 비정형 이력서의 역량·문맥 추출과 채용공고 문구 초안 작성에 사용합니다.
- **개발 AI:** 코드 검토와 수정, 테스트 사례 작성, 가상 데이터 구조 설계, 문서 작성, 브랜딩 및 화면 시안 탐색에 사용했습니다.

추천 점수와 순위를 생성형 AI에 직접 맡기지 않았습니다. 추출 결과를 정형 역량 ID에 연결한 뒤 코드로 점수를 계산하여, 결과의 근거를 추적하고 계산 로직을 반복 검증할 수 있게 했습니다. 다만 실제 LLM의 추출 결과가 달라지면 최종 추천도 달라질 수 있습니다.

## 2. 서비스 내부에서 AI를 활용한 방식

### 2.1 이력서 분석

이력서는 직무명, 기술 목록, 수행 활동, 경력 기간이 혼합된 문서입니다. 단어 대조만으로는 본인의 수행 경험과 희망사항·인용한 공고 내용을 충분히 구분하기 어렵습니다. 이에 코드의 후보 탐색과 LLM의 문맥 판단을 분리했습니다.

1. 코드가 이력서 원문에서 역량 사전의 이름과 별칭을 찾아 후보를 만듭니다.
2. LLM에 후보 목록과 사용 가능한 정규 역량 어휘를 함께 전달합니다.
3. LLM은 현재 직무, 경력, 역량 후보와 원문 근거를 JSON으로 반환합니다.
4. 코드가 응답의 필수 형식을 확인하고, 원문에서 확인되지 않는 근거를 가진 역량 후보를 제거합니다.
5. 경력 기간은 규칙으로 읽을 수 있으면 그 값을 우선하고, 역량 이름은 정형 ID로 연결합니다.
6. 매칭 코드가 직무별 적합도, 부족 역량 및 경로를 계산합니다.

프롬프트에는 원문 근거 유지, 없는 성과·기간 생성 금지, 칭찬 대신 사실 기술, 기술·도구와 수행 방식의 동시 추출을 지시했습니다. 이는 프롬프트 설계 원칙이며, 지시만으로 정확성이 보장되지는 않습니다. 현재 근거 검사는 정규화한 문자열이 원문에 포함되는지 확인하는 수준이므로, 그 문장이 실제로 해당 역량을 입증하는지까지 검증하지는 못합니다.

Gemini와 Anthropic 호출 경로가 구현되어 있습니다. 공급자와 모델은 환경변수로 선택하며, 코드 기본 모델 문자열은 각각 `gemini-flash-lite-latest`, `claude-haiku-4-5-20251001`입니다. 이는 확인 시점의 코드 설정이지 실제 사용 모델 이력이나 공급자의 현재 제공 여부를 증명하는 값은 아닙니다.

개발용 `mock`은 외부 LLM 없이 단어 탐색과 경력 규칙으로 같은 파이프라인을 실행하는 대체 구현입니다. 지정한 공급자의 키가 없으면 오류를 내며, 공급자·키 미지정 상태의 자동 mock 선택은 개발 환경에 한정됩니다. 운영 환경에서는 미설정 상태를 오류로 처리합니다.

### 2.2 적합도 계산에서 AI를 제한한 방식

개인 추천의 `fitScore`는 필수·우대 역량 커버율, 보유 역량이 해당 직무를 가리키는 정도, 경력 적합도와 현재 직무 일치 보너스를 코드로 계산합니다. 표시 적합도 중심으로 정렬하고, 동점일 때 별도의 `evidenceScore`를 사용합니다.

기업 후보 점수는 공고의 필수·우대 역량 커버율을 코드로 계산합니다. 공고 경력 범위 충족 여부는 별도 `careerFit`으로 판단합니다. 개인 점수와 기업 점수는 계산식과 평가 단위가 다르므로 같은 척도로 직접 비교하면 안 됩니다.

두 점수 모두 **현재 데이터와 규칙에 따른 매칭 지표**입니다. 합격 확률, 실제 업무 성과, 채용 성공률을 의미하지 않습니다. 부족 역량의 난이도로 계산하는 학습·온보딩 기간 역시 추정치입니다.

### 2.3 기업용 채용공고 초안 생성

기업이 회사와 직무, 경력·근무 조건, 필수·우대 역량을 선택하면 AI가 제목, 요약, 주요 업무 문구를 작성하도록 구현했습니다. 구조화된 조건은 코드에서 구성하고, LLM이 반환할 수 있는 문구 필드는 제한했습니다.

반환 JSON의 자료형과 문구 길이를 검사하며, 같은 입력 계약을 사용하는 mock 문구 생성도 제공됩니다. 초안은 기업 사용자가 검토·수정하는 대상으로 취급해야 합니다. 회사의 실제 사업 내용과 채용 조건을 AI가 확인하거나 보증하는 기능은 아닙니다. 현재 공고 초안 및 전형 상태 변경은 화면 상태 중심의 목업이며, 실제 게시·저장·지원 접수를 완료한 서비스로 설명하지 않습니다.

## 3. 개발 과정에서 AI를 활용한 방식과 결과

아래 활용 이력은 작업 대화 기록을 바탕으로 정리했습니다. 커밋은 변경 결과의 근거이며, 특정 코드 전체를 AI가 작성했다는 저자 증명은 아닙니다.

| 작업 | AI 활용 방식 | 사용자 판단·검토 | 남은 결과 |
|---|---|---|---|
| 추천 오류 분석·개선 | 사용자 이력서 사례를 출발점으로 추출·점수·순위의 원인을 검토하고 수정 및 테스트 작성에 활용 | iOS 사례와 다른 분야 사례의 결과를 확인하도록 요청하고 개선 방향을 결정 | 직무 문맥 반영, 점수와 순위 일치, 회귀 평가 코드 |
| 데이터 정제·목업 설계 | 역량 매핑 문제 점검과 가상 회사·공고·지원자 구조 설계 및 생성 작업에 활용 | 실제 정보 수집 대신 그럴듯한 가상 데이터를 사용하되 실제 데이터로 교체 가능한 계약을 요구 | 회사·공고·지원자 데이터 계약과 데모 생성·검증 경로 |
| 기업용 기능 | 공고 입력·AI 초안·추천 인재 흐름의 계획과 구현 보조에 활용 | 계획 승인 후 구현, 팀원 UI를 기준으로 별도 화면에도 디자인 적용하도록 요청 | 기업 공고 작성과 후보 조회 목업, 초안 생성 경로 |
| 기획·기능 명세 | 코드와 작업 기록을 바탕으로 기능·제약·서비스 가치를 문서화하는 데 활용 | 현재 구현과 향후 계획을 구분하고 설명용 문서를 요구 | 기획서, 기능 명세, 로드맵 등 |
| 브랜딩·화면 시안 | 브랜드 방향 탐색, Design AI 전달 문서와 이미지 시안 작성에 활용 | 개인 중심·기업 확장형 제안에서 양면 플랫폼으로 방향을 변경하고 팀원 main UI를 기준으로 지정 | 브랜딩 문서 및 화면 참고 이미지. 현재 해당 WIP는 stash 보관 |

개발 AI 도구는 작업 기록상 Codex 중심이며 화면 이미지 탐색에는 이미지 생성 AI를 사용했습니다. 서비스의 Gemini·Anthropic과 개발 보조 AI는 다른 용도입니다. 모든 팀원의 도구 사용 이력, 전체 프롬프트·응답, 정확한 모델 버전·토큰·비용은 확보하지 않았으므로 프로젝트 전체의 AI 사용량은 산정하지 않았습니다.

## 4. 확인한 결과

### 4.1 이번 작성 시점에 재실행한 결과

2026-09-14에 `npm run eval:resumes`를 실행했습니다. 테스트는 `mockExtract`에서 시작하여 추출·경력 해석·추천 계산을 연결합니다. HTTP API, 브라우저, 실제 LLM까지 포함한 E2E 테스트는 아닙니다.

- 사례 12건 중 1위 직무 평가 대상 11건: 11건 기준 충족.
- 경력 평가 12건: 12건 허용 오차 기준 충족.
- 금지 직무의 1위 노출: 0건.
- Vitest 실행 결과: 파일 1개, 테스트 1개 통과. 그 테스트 내부에서 12개 사례를 평가합니다.

### 4.2 기존 문서에 남아 있는 평가

[이력서 평가 문서](./RESUME_EVAL.md)에는 2026-09-11 기준 조사 데이터 3,420건의 Top1 32.4%, Top3 57.5%와 대체 역량 문턱 조정 과정이 기록되어 있습니다. 이번 작성에서는 해당 조사 평가를 재실행하지 않았습니다. 동일 데이터에서 문턱을 선택한 결과이므로 독립 최종 검증 성능으로 주장하지 않습니다.

실제 Gemini·Anthropic의 의미 기반 추출 정확도와 공고 생성 품질은 이번 작업에서 측정하지 않았습니다. Codex CLI를 독립 평가자로 연결한 테스트도 완료된 검증 근거로 제시하지 않습니다.

## 5. 한계와 후속 검증

1. **실제 LLM 품질 미측정:** 도구 나열, 문장형 경험, 희망 역량, 인용 공고, 부정 표현을 포함한 별도 평가셋에서 공급자·모델·시점·오류를 기록해야 합니다.
2. **역량 그룹과 데이터 편향:** 모바일 요구가 한 그룹으로 과도하게 충족될 수 있고 직무별 공고 수가 다릅니다. 요구 그룹과 낮은 표본 직무의 표시 기준을 재검토해야 합니다.
3. **규칙·수동 값의 한계:** 신입 비율과 학습 난이도 등 일부 값은 수동 설정입니다. 문서·계약 검증 통과는 그 값이 현실적으로 타당하다는 증명이 아닙니다.
4. **가상 데이터의 범위:** 기업·공고·지원자는 기능 시연용입니다. 이를 실제 고객·채용 실적 또는 추천 모델의 성능 검증 데이터로 제시하면 안 됩니다.
5. **개인정보·비용:** 실제 이력서를 외부 모델에 전달하려면 동의, 전송 항목 최소화, 보관·삭제 정책, 실패 대응과 비용 제어가 필요합니다. 이번 문서는 그 정책의 운영 완료를 증명하지 않습니다.
6. **디자인 이미지의 한계:** 생성 이미지는 참고 시안입니다. 임의 문구·수치·아이콘이 섞일 수 있어 실제 데이터와 디자인 규칙에 맞춰 검토해야 합니다. 현재 구현 화면과 구분합니다.

세부 미해결 항목은 [OPEN_PROBLEMS](./OPEN_PROBLEMS.md)을 참고합니다. 해당 문서는 기록 시점이 있으므로 현재 해결 여부는 코드와 재검증으로 확인해야 합니다.

## 6. 제출·설명용 요약

> AI는 이력서의 비정형 경험을 역량 후보와 원문 근거로 정리하고, 기업의 공고 문구 초안을 작성하는 데 활용했습니다. 적합도와 추천 순위는 AI가 아닌 정형 코드로 계산합니다. 개발 과정에서도 AI를 오류 분석, 구현 보조, 가상 데이터 설계, 문서와 디자인 시안 작성에 활용했고, 서비스 방향과 적용 범위는 사용자가 검토·결정했습니다. 현재 mock 회귀 사례 12건에서 직무 평가 11건과 경력 평가 12건이 기준을 통과했습니다. 다만 실제 LLM 품질, 객관적 점수 보정, 채용 성과까지 검증한 결과는 아닙니다.
