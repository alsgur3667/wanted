# 이력서 테스트 — 추천 결과가 말이 되는지 본다

채점기(`scripts/collect/eval_routes.py`)는 **설문 응답**으로 순위 정확도를 잰다.
이 테스트는 다른 것을 본다 — **사람이 쓴 이력서를 넣었을 때 나오는 화면이 납득되는가.**
숫자로 잡히지 않는 종류의 오류(직무 정의가 틀림, 사전에 단어가 없음, 대체 인정이 과함)를 잡으려는 것이다.

## 실행

```bash
npm run eval:resumes
```

API 키가 필요 없다. 누가 돌려도 같은 결과가 나온다.

## 어떻게 도는가

```
이력서 원문
  → mockExtract()        lib/llm.ts
      · findMentions()        사전에 있는 이름을 원문에서 찾는다
      · extractCareerMonths() 연차를 규칙으로 뽑는다        lib/career.ts
      · resolveJobTitle()     직무명을 별칭으로 맞춘다
  → buildAnalysis()      lib/scoring.ts   ← 순위·점수·경로는 전부 여기서 나온다
```

### ⚠️ 이 테스트가 못 보는 것

`mockExtract` 는 **LLM 을 부르지 않는다.** 실제 서비스에서 LLM 이 하는 판단이 빠져 있다.

- 서술형 문장에서 역량 뽑기 ("지표를 설계해" → `지표 설계`)
- 남의 얘기·희망사항 거르기 ("경력 3년 이상 우대"는 내 경력이 아니다)

그래서 **여기서 못 잡은 역량이 실제로도 못 잡힌다는 뜻은 아니다.**
반대로 **여기서 틀린 순위는 LLM 이 있어도 틀린다** — 순위·연차·직무 판정은 전부 코드가 한다.
결함을 보고할 때는 둘 중 어느 쪽인지 반드시 구분해서 적을 것.

## 케이스 — `scripts/eval/resume-cases.json`

| 칸 | 뜻 |
|---|---|
| `resume` | 이력서 원문 |
| `why` | 이 케이스로 무엇을 보려는지 |
| `expectTop` | 1위가 이 중 하나여야 한다. 빈 배열이면 1위를 채점하지 않는다 |
| `mustNotTop` | 1위가 이것이면 실패 |
| `expectMonths` · `monthsTolerance` | 연차 추출 기대값(개월)과 허용 오차 |

**기대치는 결과를 보기 전에 적는다.** 결과를 보고 기대치를 맞추면 테스트가 아니다.
케이스를 추가할 때도 같다 — 먼저 적고, 그 다음 돌린다.

## 채점을 어떻게 하나

숫자(1위 적중률·연차 적중률)는 **출발점일 뿐이다.** 통과한 케이스 안에도 틀린 것이 있다.
아래 넷을 눈으로 확인할 것.

1. **2·3위가 말이 되는가.** 1위만 맞으면 통과로 찍히지만, 화면에는 셋 다 나온다.
2. **찾은 역량 목록에 없어야 할 것이 있는가.** 짧은 별칭(`UI`, `GA`)이 엉뚱한 문장을 잡는다.
3. **찾은 역량 목록에 있어야 할 것이 빠졌는가.** 사전에 그 단어가 아예 없을 수 있다.
4. **점수가 역량 수와 거꾸로 가는가.** 필수가 3개뿐인 직무는 2개만 맞춰도 높게 나온다.

판단이 갈리면 **밖에서 확인한다.** 실제 채용 공고(원티드·인디드·잡코리아)나
직업 정보(O*NET·NCS·고용24)를 찾아 "이 직무가 정말 이걸 요구하는가"를 대조한다.
근거 없이 "맞는 것 같다"로 넘기지 말 것.

## 기준선 — 2026-09-11

```
1위 적중 10/11  ·  연차 적중 11/12  ·  금지 직무가 1위 0건
```

이 숫자만 보면 괜찮아 보이지만, **아래 결함 5건은 이 숫자에 안 잡힌다.**
다시 돌렸을 때 이것들이 그대로면 아직 안 고쳐진 것이다.

| # | 무엇 | 어디서 보이나 | 층 |
|---|---|---|---|
| 1 | 임베디드·펌웨어 필수가 Linux·C++·Python·Git 이라 아무 개발자나 들어온다. C·MCU·펌웨어·하드웨어가 필수에 없다 | `ios_8y` 2위 임베디드 60점 | 데이터 |
| 2 | `UX/UI` 별칭에 `UI` 가 있어 "UI 자동화 테스트"의 UI 를 역량으로 잡는다 | `qa_6y` 찾은 역량에 UX/UI | 사전 |
| 3 | 마케팅 어휘가 사전에 없다 — ROAS·메타 광고·퍼포먼스 마케팅이 없고 `GA4`·`Google Ads` 는 별칭이 비어 "GA"·"구글 광고"를 못 잡는다. 직무 별칭에도 "퍼포먼스 마케터"가 없다 | `marketer_2y` 1위가 데이터 분석가, 직군을 '개발'로 읽음 | 사전 |
| 4 | 서버 언어 묶음(Java·Python·C#…) 대체 인정이 데이터 사이언티스트의 Python 에도 적용된다. DS 의 Python 은 언어가 아니라 pandas·sklearn 생태계다 | `be_java_5y` 2위 데이터 사이언티스트 45점 | 점수 |
| 5 | 기간형 경력 표기("2018.03 ~ 현재")를 못 읽어 0개월로 본다 | `career_period` 연차 0 | 규칙 |

### 고쳐졌는지 확인하는 법

```bash
npm run eval:resumes
```

- #1 — `ios_8y` 의 2위가 임베디드가 아니어야 한다
- #2 — `qa_6y` 의 찾은 역량에 `UX/UI` 가 없어야 한다
- #3 — `marketer_2y` 의 1위가 마케팅·그로스여야 하고, 읽은 직무가 '경력자'가 아니어야 한다
- #4 — `be_java_5y` 의 2위가 데이터 사이언티스트가 아니어야 한다
- #5 — `career_period` 의 연차가 96~108개월이어야 한다

## 다른 사람(또는 다른 AI)에게 시킬 때

그대로 복사해서 주면 되는 지시문이다.

> 이 저장소에서 `npm run eval:resumes` 를 돌리고 결과를 분석해 주세요.
>
> 1. `docs/RESUME_EVAL.md` 의 "채점을 어떻게 하나" 네 가지를 **케이스마다** 확인하세요.
>    1위 적중률만 보고 판단하지 마세요.
> 2. 이상해 보이는 추천은 **실제 채용 공고나 직업 정보를 찾아 대조**하고,
>    출처 링크를 함께 적으세요. 근거 없이 "맞는 것 같다"로 넘기지 마세요.
> 3. 결함마다 **어느 층의 문제인지** 구분하세요 —
>    사전에 단어가 없나 / 직무 정의가 틀렸나 / 점수 계산이 틀렸나 / 규칙이 못 읽나.
>    그리고 **LLM 이 있으면 해결되는 것인지** 아닌지 적으세요("이 테스트가 못 보는 것" 참조).
> 4. 위 "기준선" 표의 결함 5건이 아직 남아 있는지 확인하고,
>    **새로 찾은 것**이 있으면 같은 형식으로 추가하세요.
> 5. 후하게 매기지 마세요. 통과로 찍힌 케이스 안에 틀린 것이 있습니다.

## 케이스를 늘릴 때

지금 12건은 적다. 늘릴 때 아래를 우선한다.

- **비개발 직무** — 지금 디자인 1건·기획 1건·마케팅 1건뿐이다. 공고 표본도 얇다(마케팅·그로스 19건)
- **경력 표기 변형** — 표·기간·"N년 N개월"·공백 기간이 있는 이력서
- **경계 사례** — 역량이 하나도 없는 글, 아주 긴 이력서, 영문 이력서
- **전환 지원자** — 지금 하는 일과 가려는 일이 다른 사람. 「이 길도 있어요」가 제대로 붙는지
