찾았지만 아직 못 고친 문제를 한곳에 모은다. **번호가 붙은 것은 GitHub 이슈가 원본**이라
여기서는 되풀이하지 않고 가리키기만 한다. 아래 본문은 **이슈가 아직 없는 것들**이다.

마지막 갱신 2026-09-11 · 브랜치 `fix/fit-score-scale`

## 이슈가 없는 것 — 여기가 원본

### 1. 모바일 개발자의 필수가 전부 한 택일 묶음이다

`requirementsOf('mobile_dev').must` 가 `Android · Kotlin · iOS` 셋뿐이고 셋 다
`mobile_platform` 묶음이라, 점수 계산에서 **한 칸으로 접힌다.** 모바일 개발자면
누구나 필수 100% 가 된다 — 변별력이 0 이다.

- **언제 생겼나** — `UI` 별칭을 어휘에서 빼면서(`synonyms.DROP`) UX/UI 의 근거가 줄어
  모바일 개발자에서 필수 → 우대로 밀렸다. `UI` 를 뺀 것 자체는 옳다(근거는 그 주석에 있다).
- **어디서 보이나** — `lib/scoring.test.ts` 의 reason 이 "필수 역량 1개 영역 중 1개 (가중 100%)".
- **왜 안 고쳤나** — `requirementsOf` 의 추림 규칙(tier × importance × lift)을 손대야 하고,
  그것은 24개 직무 전부의 순위를 움직인다. 채점기로 재면서 따로 해야 한다.
- **관련** — 같은 현상이 다른 직무에도 있는지 세어 보지 않았다. 먼저 그것부터.

### 2. `iOS` 토큰 하나가 서로 다른 두 가지를 가리킨다

- 모바일 개발자에게 — Swift · UIKit 으로 앱을 만드는 능력 (필수, 공고 9건, 무게 0.56)
- 프로덕트 디자이너에게 — Apple 휴먼 인터페이스 가이드라인 이해 (우대, 공고 3건)

둘 다 실제 공고에서 나온 것이라 데이터는 맞다. 문제는 화면에 `iOS` 라고만 뜨는 것이다.
디자이너는 "내가 앱 개발을 배우라고?" 로 읽는다. 첫 단계 문구도 무게가 큰 쪽(개발)에
맞춰 적어 뒀다(`data/first-steps.json` 주석 참조).

고치려면 스킬을 둘로 나눠야 하는데, `isCrossFamilySkill` 이 iOS 를 직군 넘나드는 역량으로
세고 있어 **히든 경로의 다리 계산이 같이 움직인다.** 따로 재야 한다.

### 3. 첫 단계 문구 234개가 아직 템플릿이다

`data/first-steps.json` 에 79개를 손으로 적었다. 화면에 뜰 수 있는 역량의 중요도 기준
83% 를 덮지만, 나머지는 여전히 type 별 템플릿이다("{n} 로 지금 손으로 하는 작업 하나를
자동화해 보세요"). 남은 것은 Ubuntu · Hadoop · Redux · Prometheus 같은 하위권이라
카드에 잘 안 올라오지만, 올라오면 바로 티가 난다.

### 4. 공고 근거가 0건인 직무-역량 행이 871개(57%)다

출처는 온톨로지(O*NET·NCS) 616 · 해설 글 183 · 수기 72.
무게가 0 이라 **점수에는 영향이 없지만 우대 목록에는 뜬다.** 백엔드·아키텍트·보안·PM 에
`iOS` 가 우대로 붙어 있는 식이다. 보여줄지 말지 방침이 필요하다.

### 5. 한국어 이력서의 맨 `GA` 를 못 잡는다

`GA4` 의 별칭으로 넣으려다 코퍼스에서 재 보니 5건 중 4건이 거짓이었다 —
`GA drawings`(General Arrangement) · `GA release`(General Availability).
그래서 **알고 두는 빚**이다. 공고 쪽과 이력서 쪽에 서로 다른 별칭을 쓰면 풀리지만,
사전이 둘로 갈리는 값을 치러야 한다.

### 6. `C` 가 어휘에 없다

임베디드의 핵심 언어인데 한 글자라 매칭이 위험하다(`C++` · `C#` 안의 C, 문장 속 C).
임베디드 필수가 Linux · C++ · Python 인 것과 직접 연결된 문제다.

### 7. 한국어 업무 역량이 어순 변형에 약하다

"광고를 집행하며" 가 `광고 집행` 과 안 맞고, "지표를 설계해" 가 `지표 설계` 와 안 맞는다.
조사는 `word_pattern` 이 처리하지만 어순은 못 한다.

⚠️ 이건 **LLM 이 붙으면 잡힌다.** `mockExtract` 경로(= 이력서 테스트)의 한계이지
서비스의 결함이 아니다. 다만 LLM 이 얼마나 잡는지는 아직 재지 않았다.

### 8. `data/samples.ts` 의 `evidenceText` 가 원문과 토씨까지 같지 않다

파일 상단 주석은 "resumeText 안의 표현을 그대로 쓴다" 고 적혀 있는데, 실제로는 어미를
명사형으로 바꾼 것이 섞여 있다(그로스 마케터 3건 · 취준생 1건이 원래부터 그랬다).
뜻은 1:1 로 대응한다. 주석을 실제에 맞추든지, 문장을 원문 그대로 바꾸든지 정해야 한다.

### 9. 샘플 4개 중 「이 길도 있어요」가 3개에만 붙는다

취업준비생(비전공 신입)에게는 직군을 건널 다리가 실제로 없어서 **안 붙는 것이 맞다.**
모두에게 붙이면 그게 거짓이다. 다만 발표에서 4개 중 3개만 보인다는 것은 알고 있을 것.
